# Bodycam build calculator

[English](README.md) · Русский

Калькулятор билдов оружия для Bodycam. Открыть: `web/index.html` (просто файл в браузере, сервер не нужен).

Одним файлом: `bodycam-build-calc.html` — собирается из `web/` командой `python3 tools/bundle.py web bodycam-build-calc.html` (и автоматически в конце `update.sh`). Править нужно файлы в `web/`, не его.

- `web/` — страница (`index.html`, `app.js`, `core.js` — логика расчёта без DOM, `i18n.js` — строки интерфейса) и данные (`data.js`, `data.json`).
- Язык интерфейса выбирается в шапке страницы (английский по умолчанию, русский); выбор запоминается в браузере. Новый язык — ещё один блок в `web/i18n.js`.
- `tools/` — выгрузка данных из установленной игры (только чтение `.pak`):
  `paklist.py`/`pakextract.py` (индекс и распаковка pak v11 + Oodle), `uasset.py` (заголовок ассета),
  `items.py` (таблица предметов `DT_WeaponItems`), `geparse.py` (модификаторы GameplayEffect), `build_data.py` (сборка `data.js`).
- `update.sh [путь к игре]` — пересобрать данные после патча. Нужен venv: `python3 -m venv .venv && .venv/bin/pip install pyooz`.

## Как считается

- База оружия — из `GE_WeaponStat_*`, вклад обвесов — из `GE_AttachmentStat_*`.
- Множители одного параметра складываются (как в GAS): `итог = база × (1 + Σ(множитель − 1))`.
- `ADSSpeed`, `SwitchSpeed`, `ReloadTime` — множители скорости (больше = лучше): `время = базовое время ÷ множитель`.
- Базовое время перезарядки/доставания — длительность first-person анимаций оружия (среднее по вариантам).
- Совместимость — по тегам `обвес → оружие`; один обвес на слот.

## Чего в данных нет / допущения

- Базовое время ADS — оценка: момент, когда кривая движения «в прицел» (`*_Aim_In_Loc`, набор `Additive_*_Aim_In`) проходит 95% пути. Что именно игра считает «прицелился» и масштабируется ли кривая множителем `ADSSpeed`, из данных не видно; своё значение можно ввести вручную.
- Обвесы, отключённые в таблице магазина игры или не внесённые в неё, по умолчанию скрыты.
- Слот доступен, только если у оружия (скелет модели) или у установленной детали (сокеты меша) есть крепление с именем слота. У SKR-H данных о креплениях ресивера нет — для него ограничения не применяются.
- У нескольких обвесов в данных игры стоит «заменить параметр на 0» (похоже на заглушки) — они помечены ⚠ и в расчёт не входят.
- Парсеры эвристические (ассеты без схемы свойств); после крупного патча стоит проверить вывод `update.sh`.
